# יומן המשימות של אופיר — והצוות

פלטפורמת יומני משימות, עצמאית לחלוטין — Next.js + Supabase, עברית/RTL, מותאמת לאייפון.
לאופיר יש יומן משלו + **דשבורד צוות**; לכל איש צוות יש יומן מלא משלו, עם כל אותן יכולות.
התראות שקופצות בטלפון — **בחינם**: טלגרם או התראות מהיומן עצמו (Web Push).

## צוות ודשבורד מנהל

| כתובת | מה זה |
|---|---|
| `/` | היומן של אופיר + טאב **הצוות** (דשבורד המנהל) |
| `/j/<id>` | היומן של איש צוות — אותו יומן בדיוק, בצבע אישי |

- **הוספה לצוות**: בטאב "הצוות" ← "הוספה לצוות" ← שם, תפקיד וצבע. מתקבל קישור אישי
  לשליחה בוואטסאפ.
- **דשבורד הצוות**: כרטיס לכל אחד (להיום / בתהליך / באיחור / הושלמו השבוע / % התקדמות),
  "דורש תשומת לב" (באיחור + קריטיות, סימון ✓ בלחיצה), "היום בצוות" לפי אדם, גרף השלמות
  14 ימים, פעילות אחרונה, והקצאת משימה בעברית חופשית ("להכין מצגת ביום חמישי ב-10:00").
- **כל המשימות של איש הצוות, עם שליטה מלאה**: בטאב "הצוות" ← "כל המשימות" (או מהפס "הצוות"
  בדשבורד הראשי). לשוניות פתוחות / בתהליך / באיחור / קריטיות / הושלמו / הכל, חיפוש, מיון
  (יעד / עדכון אחרון / פתיחה), ולכל משימה: קידום סטטוס, ✓ בוצע, פתיחה מחדש, עריכה מלאה
  (כולל שלבים, תזכורות וקבצים), ומחיקה עם "ביטול". רואים גם מתי כל משימה עודכנה לאחרונה.
  כל שינוי נשמר ישר ביומן של איש הצוות ומתעדכן אצלו בזמן אמת.
- **📣 בקשת עדכון**: כפתור בכל משימה פתוחה של איש הצוות — קופצת לו/ה התראה "אופיר מבקש עדכון"
  (לכל היותר פעם בחצי שעה לאותה משימה).
- **ניהול הצוות**: רשימת כל אנשי הצוות עם כפתורי עריכה (שם, תפקיד, צבע), קישור אישי ו**מחיקה**.
  המחיקה נפתחת בדיאלוג אישור של היומן (לא `confirm()` של הדפדפן, שנחסם בחלק מהדפדפנים הפנימיים),
  ומוחקת את היומן של איש הצוות; היומן של אופיר לא משתנה. מגיעים לשם גם מ"ניהול ומחיקה" בכרזת הצוות.
- **משימה משותפת**: בחלון המשימה ← "משימה משותפת" ← "שיתוף עם נדין" (ואצל נדין: "שיתוף עם אופיר").
  המשימה נשמרת **בשורה אחת** אצל מי שיצר אותה, עם `sharedWith`, ומופיעה בשני היומנים — שניהם
  מעדכנים ומסמנים את אותה משימה, והתזכורות קופצות לשניהם. מי שלא יצר אותה רואה "הסרה מהיומן שלי"
  במקום מחיקה (המשימה נשארת אצל היוצר). לכל צד הקטגוריה שלו (`sharedCats`), כי לכל יומן קטגוריות משלו.
- **משימה מוקצית** נוחתת ביומן של איש הצוות עם תגית "מאופיר" + התראה בטלפון שלו.
- **בלי קוד ובלי מסך נעילה** (הוסר לבקשת המשתמש): היומן של אופיר והדשבורד נפתחים ישר מהכתובת
  הראשית. ⚠️ לכן כל מי שמחזיק בכתובת הראשית — כולל איש צוות — יכול לפתוח את היומן של אופיר.
  שורת `manager_pin` ישנה ב-`journal_meta`, אם קיימת, פשוט לא בשימוש.
- **אין צורך במיגרציה**: שיוך משימה ליומן נשמר בתוך ה-payload (`journalId`); משימות קיימות
  בלי שיוך שייכות לאופיר. הגיבוי הלילי והשחזור ממשיכים לעבוד כמו שהם.

## היומן כאפליקציה בטלפון

בדשבורד מופיע באנר "היומן כאפליקציה בטלפון" (נעלם אחרי ההתקנה, או ל-14 יום ב"לא עכשיו"):

- **אנדרואיד / Chrome:** כפתור "התקנה" פותח את חלון ההתקנה של הדפדפן בלחיצה אחת.
- **אייפון:** "איך מתקינים" מציג את השלבים — Safari ← שיתוף ← "הוספה למסך הבית".
- **הקישור נפתח בתוך וואטסאפ / אינסטגרם?** משם אי אפשר להתקין. הבאנר מזהה את זה ומציע
  "פתיחה ב-Chrome" / "פתיחה ב-Safari" (או העתקת הקישור).
- לכל יומן `manifest` ואייקון משלו (`/j/<id>/manifest`, `/j/<id>/icon`) — האייקון של איש הצוות
  בגוון האישי שלו, ולא האייקון של אופיר.

## התראות לטלפון — בחינם

התראה שקופצת בטלפון, גם כשהיומן סגור. שתי דרכים, שתיהן **חינם לגמרי**:

### 1. טלגרם (מומלץ — הכי אמין, בלי תלות באייפון/אנדרואיד)

הגדרה חד-פעמית של אופיר (~2 דקות):

1. בטלגרם: [@BotFather](https://t.me/BotFather) ← `/newbot` ← שם (למשל "היומן של אופיר") + שם משתמש שמסתיים ב-`bot` ← מעתיקים את הטוקן.
2. ב-Vercel → Settings → Environment Variables: `TELEGRAM_BOT_TOKEN=<הטוקן>` ← Redeploy.

ואז כל אחד (אופיר, נדין) ביומן שלו: כפתור הפעמון ← **חיבור טלגרם** ← Start. ההתראות
כוללות כפתורי "✓ בוצע" / "⏰ עוד שעה", ובבוט יש `/today`, `/team` (למנהל), `/stop`.

### 2. התראות מהיומן עצמו (בלי אפליקציה)

כפתור הפעמון ← **הפעלת התראות במכשיר הזה**.
- **אנדרואיד:** עובד מיד ב-Chrome.
- **אייפון:** קודם Safari ← שיתוף ← **"הוספה למסך הבית"**, פותחים את היומן מהאייקון, ואז
  מפעילים (iOS 16.4 ומעלה). היומן מציג את ההוראות האלה לבד.
- תזכורות מתוזמנות כשהיומן סגור דורשות שה-cron ב-Supabase ירוץ (ראו "התראות Web Push" למטה).
  "אבחון מלא" בכפתור הפעמון מראה בדיוק מה חסר.

**מה קופץ אצל מי:**

| אירוע | אופיר | נדין / איש הצוות |
|---|---|---|
| תזכורת שהגיע זמנה | ⏰ שלו | ⏰ שלה |
| בריף בוקר · סיכום שבועי · משימות תקועות | שלו + תמונת מצב הצוות | שלה |
| איש צוות סיים / הוסיף משימה | ✅ / 📝 | — |
| אופיר הקצה משימה | — | 📌 |
| שומר תקלות | 🚨 | — |

אפשר לכבות סוגי עדכונים בדשבורד הצוות ← "עדכונים ופרטיות".

### SMS (אופציונלי, בתשלום)

הקוד תומך גם ב-SMS דרך Twilio (כמה סנטים להודעה). **כבוי כברירת מחדל ולא מוצג ביומן**
עד שמגדירים `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_FROM` ב-Vercel. אם מפעילים:
אימות מספר בקוד SMS, מספרים נשמרים מוצפנים, ומגבלות על קודי אימות (45 שניות / 5 בשעה /
25 ביום). פרטים ב-`.env.example`.

## יכולות

- **5 תצוגות**: דשבורד (לוח שנה + רשימה + מדדים), אג'נדה שבועית, טבלה ממיינת, קנבן עם גרירה, אנליטיקות
- **משימות**: קטגוריות צבע חופשיות, מהות (אישי/דחוף/שוטף), קריטיות, תאריך יעד (מוצג בלוח), תאריך סיום
- **תזכורות** לפי תאריך ושעה (התראת דפדפן + התראה באפליקציה)
- **קבצים מצורפים** לכל משימה
- **תתי-משימות (שלבים)** רקורסיביים — לכל שלב כל המאפיינים של משימה
- **סטטוסים**: לביצוע → בתהליך → הושלם
- **סינון מורכב** מסרגל צד: קטגוריות, מהות, סטטוס, קריטיות, חיפוש חופשי
- **סנכרון ענן** דרך Supabase, עם נפילה חלקה ל-localStorage אם אין חיבור

## הגדרה (פעם אחת)

### 1. Supabase
1. היכנס לפרויקט ה-Supabase הייעודי (הנפרד) → **SQL Editor**
2. הרץ את התוכן של [`supabase-schema.sql`](./supabase-schema.sql)
   (יוצר את הטבלאות `journal_tasks` + `journal_meta` ומפעיל realtime)
3. העתק מ-**Project Settings → API** את:
   - `Project URL`
   - מפתח `anon public`

### 2. משתני סביבה
העתק את [`.env.example`](./.env.example) ל-`.env.local` ומלא את שני הערכים:

```
NEXT_PUBLIC_SUPABASE_URL=https://XXXXXXXX.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=...
```

### 3. פיתוח מקומי

```bash
npm install
npm run dev
```

פתח http://localhost:3000

## פריסה ל-Vercel

1. **New Project** → ייבוא הריפו הזה
2. הוסף את שני משתני הסביבה שלמעלה (Environment Variables)
3. **Deploy** — מקבלים כתובת ייעודית משלו

בלי משתני הסביבה האפליקציה עדיין עובדת, אך שומרת מקומית בלבד (חיווי "מקומי בלבד").

## התראות Web Push (תזכורות כשהיומן סגור)

תזכורות מגיעות כהתראת מערכת גם כשהיומן סגור, דרך Web Push:

1. **מפתחות VAPID** — צור עם `npx web-push generate-vapid-keys` והוסף ל-Vercel:
   `NEXT_PUBLIC_VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` (mailto), ו-`CRON_SECRET` (מחרוזת אקראית).
2. **Supabase** — הפעל את התוספים `pg_cron` ו-`pg_net` (Database → Extensions), ואז הרץ את
   [`supabase-cron.sql`](./supabase-cron.sql) (יוצר את כל הטבלאות ומתזמן את כל המשימות, כולל זו שכל דקה קוראת ל-`/api/send-reminders`).
3. **במכשיר** — לחץ "הפעל התראות" ביומן ואשר. באייפון: קודם "הוסף למסך הבית" (Web Push נתמך רק ב-PWA מותקן, iOS 16.4+).

הזרימה: `pg_cron` (כל דקה) → `/api/send-reminders` → מאתר תזכורות שהגיע זמנן → שולח Web Push לכל המכשירים הרשומים.

**אבחון**: כפתור הפעמון בסרגל פותח את "עדכונים לטלפון" ← **אבחון מלא**: SMS, טלגרם, הרשאת
הדפדפן, האם המכשיר רשום (וגם קיים בענן), מפתחות חסרים ב-Vercel, האם ה-cron רץ ומתי,
וכשלי מסירה אחרונים מהשרת (למשל 403 ממפתחות VAPID שהוחלפו) — כולל השלב המדויק שחסר.

**תיקוני אמינות לפוש (V5):** המכשיר מרענן את המנוי בשרת בכל פתיחה (מרפא מנוי שנמחק);
ה-Service Worker מטפל ב-`pushsubscriptionchange` (הדפדפן מחליף מנוי בשקט); כשלי מסירה
נרשמים ל-`automation_log` ומופיעים באבחון וב-`/api/health`; כל מכשיר משויך ליומן שלו, כך
שתזכורות של איש צוות לא מגיעות לטלפון של אופיר ולהפך.

> ⚠️ הריפו ציבורי — **אין לשמור את `CRON_SECRET` באף קובץ.** הוא נשמר בטבלה
> `app_config` ב-Supabase, שמוגנת ב-RLS בלי אף policy ולכן מפתח ה-anon הציבורי
> לא יכול לקרוא אותה. מתזמני ה-cron קוראים את הערך משם.

## אוטומציות מתוזמנות

מעבר לתזכורות, היומן מריץ חמש אוטומציות. כולן פועלות בשרת (Vercel) ומתוזמנות
ע"י `pg_cron` ב-Supabase — בלי תלות במחשב או בדפדפן פתוח.

| אוטומציה | מתי | מה קורה |
|---|---|---|
| ☀️ בריף בוקר | כל יום 07:00 | משימות היום, קריטיות ומה שבאיחור |
| 📊 סיכום שבועי | חמישי 16:00 | מה הושלם, כמה נותר, אחוז התקדמות |
| 🕸️ משימות תקועות | ראשון 08:00 | תקועות ב"בתהליך" מעל שבועיים / באיחור מעל שבוע |
| 💾 גיבוי | כל לילה 02:00 | תמונת מצב ל-`journal_backups` (30 האחרונות) |
| 🚨 שומר תקלות | כל 15 דקות | מזהה שהתזכורות נעצרו או שהאתר נפל |

**הפעלה:**

1. **Supabase** — הרץ את [`supabase-cron.sql`](./supabase-cron.sql). זה הקובץ היחיד
   שצריך: יוצר את כל הטבלאות ומתזמן את חמש המשימות. הדבר היחיד לערוך בו הוא
   שורת הסוד המסומנת ב-✏️ (שלב 2 בקובץ). בטוח להריץ שוב בכל עת.
2. **שומר התקלות** — רץ מעצמו דרך GitHub Actions
   ([`.github/workflows/watchdog.yml`](./.github/workflows/watchdog.yml)). הוא מאוחסן
   אצל GitHub ולכן מזהה גם נפילה של Vercel או של Supabase. בכישלון הוא מסמן את
   הריצה כאדומה — וגיטהאב שולח מייל לבעל הריפו.
3. **מייל (אופציונלי)** — בלעדיו נשלחות רק התראות פוש. להוספה: מפתח מ-
   [resend.com](https://resend.com), ואז `RESEND_API_KEY` + `ALERT_EMAIL_TO` ב-Vercel.
   לשליחה לכתובת חיצונית יש לאמת דומיין ב-Resend; בלי אימות דומיין Resend שולח
   רק לכתובת שאיתה נרשמתם.

**בדיקה ידנית:**

```bash
curl https://ofir-task-journal.vercel.app/api/health          # דופק המערכת
curl -X POST -H "x-cron-secret: <SECRET>" \
  "https://ofir-task-journal.vercel.app/api/scheduled?job=morning-brief"
```

`/api/health` ציבורי אך מחזיר בוליאנים ומספרים בלבד — בלי ערכים רגישים.
הוא מדווח על תקלה גם כשגיבוי מעולם לא רץ, ולכן אחרי ההתקנה כדאי להריץ גיבוי
אחד ידנית (הפקודה בסוף [`supabase-cron.sql`](./supabase-cron.sql)) כדי לקבל ירוק.

**איפה רואים כל אוטומציה:** ארבע המתוזמנות ב-Supabase → Database → Cron;
שומר התקלות ב-GitHub → Actions; ובודק הבאגים (רוטין של Claude, נפרד מהאפליקציה)
ברשימת ה-Routines.

**שחזור מגיבוי:** ההוראות בתחתית [`supabase-cron.sql`](./supabase-cron.sql).

```
    server/       אוטומציות, SMS (Twilio), טלגרם, תקצירים, עדכוני צוות
```

## הערה על אבטחה

אין התחברות ואין מסך נעילה — מדיניות ה-RLS פתוחה למפתח ה-anon. הקישור ליומן של איש צוות
הוא אקראי (`/j/<8 תווים>`), אבל הכתובת הראשית (`/`, היומן של אופיר והדשבורד) פתוחה לכל מי
שמכיר אותה, וטכנית כל מי שמחזיק במפתח ה-anon (שנמצא בקוד שנשלח לדפדפן) יכול לקרוא ולערוך את
כל היומנים. להפרדה אמיתית בין אנשים — יש להוסיף Supabase Auth ולהדק את מדיניות ה-RLS.
